## 当前产品功能

### 观影监控与提醒

- Windows Forms 托盘程序。
- 监控 PotPlayer 的当前影片、真实播放状态、观看时间和完成比例；暂停及大幅拖动不计入有效观看时间。
- 启动使用独立配置目录的 Chrome 或 Edge 观影浏览器，不污染日常浏览器配置。
- 当前在线视频读取重点支持爱奇艺：片名、年份、类型、时长、播放进度和暂停状态。
- 达到设置的最少观看时间和完成比例后进入提醒流程。
- 支持影片身份确认、IMDb 信息、评分、7 道观点问题、AI 中文短评、稍后处理和快捷测试。

### 豆瓣历史与影片详情

- 从独立观影 Chrome 导入豆瓣“看过、想看、在看”历史。
- 本地历史支持分页、搜索、排序、海报、个人评分、豆瓣评分、标签、短评和观看状态。
- 影片详情可保存标题、年份、类型、片长、地区、导演、IMDb、剧情简介和海报。
- 首页主演严格保留豆瓣详情页可见顺序，最多显示 8 人；显示姓名和头像。
- “查看全部演职员”读取豆瓣 `/celebrities` 页面，显示全部人员的姓名、头像和岗位。
- 某人没有头像时仍保留姓名和岗位，头像位置显示空白，不遗漏人员。
- 首页主演 `Cast` 与完整演职员 `FullCast` 分开保存，禁止依赖图片数组索引配对。

### 豆瓣头像链路

- 禁止截图；截图视为读取失败，没有截图兜底。
- 不接第三方人物 API。
- 通过 Chrome CDP 读取豆瓣真实 DOM，覆盖 `src`、`currentSrc`、`srcset`、常见懒加载属性和 CSS `background-image`。
- 保存豆瓣原始头像 URL，再由程序下载图片；请求使用豆瓣 Referer。
- WebP 地址优先尝试豆瓣同路径 JPEG 变体，失败后才回退原始 URL。
- 最多 4 路并发下载，单人失败不影响其他人员。
- 头像按原始 URL 写入最多 300MB 的本地缓存；命中后直接显示，超过上限按最近使用时间淘汰旧图片。
- 头像 HTTP、内容类型、解码和缓存命中情况写入诊断日志。

### 后台 Chrome 行为

- 可以首次显示观影浏览器供用户登录豆瓣。
- 已有登录数据后，“我的观看历史”详情读取使用后台 CDP Target，不要求用户手动打开浏览器，也不激活或弹出观影浏览器窗口。
- 每次读取完成后通过准确的 Target ID 关闭程序创建的临时页面。
- 连接时静默清理精确的 `about:blank` 和程序专用标记页；不会按域名清理，不关闭真实豆瓣、爱奇艺或其他页面。
- 主详情流程为了补齐头像而已经读取完整演职员时，会同步保存 `FullCast`；之后点击“查看全部演职员”不再重复访问豆瓣。

## 新功能开发规则

1. 从 `stable-v0.8.6` 建立新分支，不在稳定标签或 v0.8.6 发布目录内直接修改。
2. 默认下一版本使用 `0.8.7`；如果功能规模较大，再单独确定版本号。
3. 先检查现有执行链和真实日志，保持当前架构，不因新增功能重写豆瓣读取链路。
4. 不重新引入演员简介卡片、截图兜底或第三方人物 API，除非用户在新任务中明确改变需求。
5. 每个版本必须有独立版本号、Git 提交、标签、明确改动目录、内置自检和不可覆盖发布目录。
6. 构建发布继续使用 framework-dependent 单文件方式，不携带完整 .NET 运行时和大量依赖 DLL。
7. 新功能不能破坏稳定验收项：简介、首页 8 人、全部演职员姓名/岗位/头像、后台无弹窗、Target 清理、缓存读取。
