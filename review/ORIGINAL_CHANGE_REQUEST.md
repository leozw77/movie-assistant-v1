上一个压缩包没有实现统一保存按钮。它只修改了：

1. `BrowserCdpService.cs`：CDP JSON 信封、脚本异常上下文、简介/JSON-LD 回退、演职员头像多级提取、占位头像过滤、递增 CDP 命令 ID、连续脚本失败诊断。

## 3. 当前最重要的需求：一个统一保存按钮

当前 UI 仍有三个独立操作：

- 提交状态
- 提交评分
- 保存短评

目标 UI 应接近豆瓣原生编辑弹窗：

- 状态单选：想看、在看（仅当官方页面提供）、看过
- 五星评分
- 短评，最多 330 字
- 一个唯一的“保存”按钮
- 删除豆瓣个人记录继续作为独立危险操作
- 第一阶段标签写入暂缓

不要只把三个旧 C# 方法串行调用。那仍然会产生部分成功。推荐新增统一操作，例如 `saveDoubanEntry`：

```text
HTML 固定用户快照
  -> C# 读取官方影片页
  -> 探测官方表单能力
  -> 提交前校验状态/评分/短评
  -> 一次官方表单填写全部字段
  -> 点击官方保存/提交控件
  -> 返回 Subject 页面
  -> 重新读取官方 interest/rating/comment
  -> 全部确认后才更新本地镜像
```

关键约束：

- 想看状态不能同时提交评分；前端禁用只是体验，C# 必须再次校验。
- 评分未选择应使用 `null`/未提交语义，不要把 0 当成真实评分。
- 官方不提供请求状态、评分或短评控件时，提交前阻止，不得更新本地。
- 等待表单和回读应使用条件轮询加最大超时，不要只写死 `Delay(3000)`。
- 操作官方 DOM 和官方按钮；不要直接 POST、`fetch`、Cookie 导出/复制或直接调用私有接口。

## 4. 保存结果和错误模型

保存成功后必须返回官方回读后的完整状态，而不是只返回“写入成功”。建议 `write` 至少包含：

```json
{
  "phase": "submitting|confirmed|blocked|failed|unconfirmed",
  "stage": "snapshot|formProbe|domFill|submit|readback",
  "requested": { "status": "collect", "rating": 5, "commentLength": 12 },
  "official": { "status": "collect", "rating": 5, "comment": "..." },
  "localUpdated": true,
  "error": ""
}
```

错误必须保留具体原因，例如：

- 无法固定当前豆瓣用户快照
- 官方表单不提供请求状态
- 官方评分控件缺失
- 官方短评控件缺失
- 官方提交按钮缺失
- 官方详情页回读未确认写入
- 登录失效、验证码、风控或网络错误

失败或未确认时：

- `localUpdated=false`
- 不更新本地豆瓣镜像
- 不更新软件真实观看记录
- 保留重试和重新读取入口
- 日志保留阶段、URL、页面标题、官方 DOM 诊断，但不要记录 Cookie 或敏感凭据

当前 `app.js` 的通用 `catch` 仍会把异常压缩成“操作失败，请稍后重试”；修改时不要丢失 `error.message` 和后端具体错误。

## 5. 删除流程

删除仍然独立于统一保存：

- 只能点击当前影片个人区域内唯一官方删除控件。
- 自动处理豆瓣官方 JavaScript 确认弹窗。
- 删除后重新读取影片页和想看/在看/看过三个列表。
- 全部确认不存在后才写本地 tombstone。
- 删除失败或未确认时不得写 tombstone。
- 不删除软件真实观看记录、影片详情、搜索、海报、演员或头像缓存。

## 6. fixed ZIP 修复的选择性采用建议

建议采用或评估：

- `EvaluateAsync` JSON 信封和异常上下文。
- 详情简介的 DOM/Open Graph/JSON-LD 回退。
- 演职员头像的懒加载、`srcset`、CSS 背景和占位图过滤。
- 对应的自测。

需要谨慎：

- 连续 3 次脚本异常即停止，需真实页面验证是否误判短暂加载波动。
- 扩大的头像选择器可能抓到海报或其他图片，必须验证演员与头像对应关系。
- JSON 信封要求所有脚本保持“可求值表达式”和可 JSON 序列化返回值。
- 固定字符串比较状态不可取，应比较规范化内部值 `wish/do/collect`。

## 7. 数据分离和安全边界

必须继续分离：

- 软件真实观看记录
- 豆瓣想看/在看/看过状态
- 豆瓣在线搜索缓存
- 豆瓣影片详情缓存
- 我的评分
- 豆瓣公众评分
- 影片身份、Cast、FullCast、海报、头像缓存

本地 HTML WebView2 与豆瓣 WebView2 必须隔离；登录、后台同步、写入操作继续互斥。

## 8. 修改前后验收标准

### 编译和静态检查

- 主程序 `dotnet build --no-restore`：0 错误。
- 内置 `--self-test`：全部通过。
- `app.js` 和所有 C# 内嵌 JavaScript：`node --check` 通过。
- 不引入直接 POST、`fetch`、Cookie 导出/复制。

### 真实功能回归

在登录的豆瓣 WebView2 中至少验证：

1. 看过 + 评分 + 短评一次保存。
2. 状态修改后界面返回官方新状态。
3. 想看时评分被禁用，并且 C# 仍然拒绝非法请求。
4. 官方评分控件缺失时提交被阻止，错误可读，本地不变。
5. 回读不确定时本地不变，并可重试。
6. 删除确认成功后 tombstone 生效，真实观看记录和缓存保留。
7. 详情简介、首页演员和完整演职员头像没有回归。
