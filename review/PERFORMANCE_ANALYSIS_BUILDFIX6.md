# BuildFix6 性能与清除评分修正

## 诊断结论

BuildFix5 已经使普通保存明显加快。日志中一次正常“看过→在看并修改评分”的完整流程，从保存前官方读取开始到最终官方回读确认约 7.2 秒；其中提交、结算和回读约 4.2 秒。

剩余详情页慢点有两个：

1. 软件启动或切换标签时会立即执行在线历史页读取，隐藏 WebView2 被历史导航占用，用户随后点击详情只能排队。
2. 详情元数据读取会先打开一次官方评价表单探测状态能力，随后 v2 官方评价读取又打开同一表单，职责重复。

BuildFix6 改为：

- 启动和切换标签只显示本地缓存。
- 在线历史同步由用户点击“刷新”触发。
- 详情元数据跳过旧状态能力表单探测，由紧随其后的 v2 官方评价快照一次性提供状态、评分、短评和能力。
- 官方表单稳定采样仍要求连续两次一致，但采样间隔缩短。

## 清除评分真实原因

实际豆瓣表单返回：

```text
ratingControlCount=6
clearRatingControlCount=0
```

这不代表存在 `star0`。第六个以 `star` 开头的元素可能是星级容器，而不是零星控件。BuildFix4/5 对 `img#star0` 的推断不成立。

BuildFix6 不直接修改隐藏评分字段。没有独立清除按钮时，使用官方可见状态控件：

```text
切换到想看
→ 只读检查官方隐藏评分已清空
→ 切回用户要求的最终状态
→ 再检查评分仍为空
→ requestSubmit()
→ 等待真实结算
→ 官方表单回读逐字段确认
```

任何一步不符合预期都会停止提交或返回失败/不确定，本地缓存不会写入目标值。
